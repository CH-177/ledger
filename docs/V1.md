# Ledger V1: completion record

V1 was completed with version 1.9.0 (September 27, 2026). All twelve phases of the master brief
are done. This page records how each part meets the brief's **Definition of Done** (§43), what V1
deliberately leaves out, and what needs yearly upkeep.

## Scope (brief §32)

| V1 scope item | Where | Since |
|---|---|---|
| Dashboard: balances, monthly income and spending, budget progress, upcoming events, goals | Overview | 1.6.0 |
| Transactions: add, edit, delete (with undo), search, filter, categories | Transactions | 1.2.0 |
| Accounts: add, edit, archive, balance calculation | Accounts | 1.0.0 |
| Budget: monthly budgets, planned vs actual, remaining | Budget | 1.2.0 |
| Recurring: income, expenses, forecasted upcoming events | Bills | 1.4.0 |
| Goals: target, current amount, progress, target date | Goals | 1.5.0 |
| Data: backup, restore, CSV export, JSON export | Settings → Data | 1.7.0 |
| Extras the user asked for: Income Calculator (paycheck prediction with PA taxes), automatic breaks, auto-recorded bills, Reports | Income, Bills, Reports | 1.3.0–1.8.0 |

## Definition of Done (brief §43)

| # | Criterion | How it's met and checked |
|---|---|---|
| 1 | Works through the UI | Every feature was used through the real interface on a sandbox database. `scripts/smoke-test.ps1` repeats the core click-through in one command. The trimmed Release build was click-tested separately (1.8.0). |
| 2 | Data persists after restart | SQLite with a checkpoint on close. Restarts were exercised in testing (restore relaunch, auto-record not duplicating after restart). The window placement persists too. |
| 3 | Calculations are tested | 353 tests against a real SQLite database with the production migrations. Each rule in `docs/RULES.md` names its tests. |
| 4 | Invalid input is handled | Services validate every write with friendly messages (amounts, dates, names, accounts, categories, schedules, goals, backups). The database has CHECK constraints and foreign keys as a second line (`DatabaseTests`, `InvariantTests.The_schema_has_…`). |
| 5 | Empty states are handled | Every page was audited on a brand-new database (1.8.0). |
| 6 | Errors are handled | No raw exceptions reach the user. Pages show "…Your data hasn't been changed" with Try Again, and technical details go to the local log without financial content (§24). |
| 7 | Light and dark themes | Every page was audited in both (1.8.0). |
| 8 | No duplicate financial records | Recurring posting is unique per date (database index). Auto-record is idempotent across restarts. Paycheck records are unique per period. Pasting a schedule replaces rather than duplicates. |
| 9 | Historical information is never corrupted | Soft delete. RESTRICT foreign keys. Balances are derived, never stored. Every schema upgrade is backed up first and tested against real older databases. `InvariantTests` proves that forecasts, reports and exports never write. |
| 10 | Follows the visual language | Calm Fluent design from theme tokens. Colour always has words beside it, and forecasts are always labelled as forecasts. |

Cross-cutting guarantees are enforced by `tests/Ledger.Core.Tests/InvariantTests.cs`:
- Reading never changes stored data.
- Money is conserved, and transfers never change net worth (randomized, fixed seeds).
- The Dashboard, Budget, Reports and Transactions pages report the same totals.
- A deleted transaction counts nowhere, and restoring it counts everywhere.
- Goal math can never produce invalid values.

## Deliberately not in V1 (brief §33)

No bank connections, cloud, accounts or sync. No investments, crypto, credit scores or tax filing.
No AI or OCR. No charts beyond simple bars. Ledger never sends data anywhere.

## Candidates for later versions

- **Income Calculator:**
  - Deductions (401(k), health insurance).
  - Checking an estimate against a real paystub.
  - A tax set-aside for side income.
  - Confirming the real Riverside Market payday once a paystub arrives (currently assumed: the Friday after
    each Sunday–Saturday week).
- **Brief items designed for but not built:**
  - Bank CSV import with duplicate detection (§25–26).
  - Sinking funds (§14).
  - Refunds as their own transaction type.
- **Portability:** a Swift/SwiftUI version can be built against `docs/RULES.md` (the tests are the
  specification) and `docs/EXPORT_FORMAT.md`. See `docs/PORTABILITY.md`.

## Yearly upkeep

- **Tax tables.** Paycheck estimates use `src/Ledger.Core/Data/Reference/tax-2026.json` (IRS
  Pub 15-T, FICA limits, PA rates).
  - Each December, add `tax-YYYY.json` for the new year from the new Pub 15-T.
  - Until then, Ledger uses the latest year it has and says so on each paycheck.
- **Local earned income tax.** Maple Boro's 1.5% comes from the 2025 PA statewide list and was
  not re-verified for 2026. It's in Settings → Local tax.
- **Updating the app:** run `scripts/install.ps1` (Ledger must be closed). Every upgrade that changes
  the database saves a backup first.
- **Sharing a release:** run `scripts/package.ps1` after bumping the version; give people
  `dist/Windows-v<version>/` (the Setup, the portable zip and README.txt). A new year's tax tables are
  a good reason to share a new build.
